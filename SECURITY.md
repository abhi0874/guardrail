# Security policy

## Reporting

For a future public repository, the maintainer should enable GitHub private vulnerability reporting and verify that the Security tab accepts reports before publication. Once enabled, use **Security → Report a vulnerability**. Keep credential values, account data and sensitive details out of public issues, pull requests and CI logs.

Include the affected version, the boundary involved, the impact and a sanitized description. Use synthetic accounts and local fixtures to demonstrate supported behavior. The maintainer will coordinate remediation and disclosure privately.

## Scope

The public dashboard and recruiter walkthroughs use synthetic data. The privately operated account-enabled application and restricted backend have separate operator controls. The deployment notes explain the private application’s outstanding password-recovery limitation. [Deployment status](docs/DEPLOYMENT_STATUS.md)

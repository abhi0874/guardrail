# Verification

The MCP suite uses a disposable PostgreSQL instance and enforces 95% source coverage. Install the frozen root environment and run `make check` with the disposable database settings documented in the CI workflow. Run the passive MCP classifiers with `uv run --frozen pytest -q --no-cov security-tests/test_observation_classifiers.py`.

The [Scanner](../security-tests/scanner/README.md) has its own frozen environment. Its original rules benchmark contains 175 project-generated fixtures. On the 120-case evaluation split it recorded 48 true positives, 66 true negatives and six abstentions. Eight evaluation rows share exact detector inputs with development rows. The remaining 112 rows produced 44 true positives, 62 true negatives and six abstentions. See the [benchmark methodology](../security-tests/scanner/DETECTOR-METHODOLOGY.md) for denominators and the original evidence. These synthetic results do not establish production accuracy. The earlier MCP receipt evaluation was a different experiment. Its historical results were 140 true positives, 96 true negatives and four abstentions on 240 synthetic cases. That complete collection harness and dataset are outside this distribution. The legacy v2 observer has a known common-mode receipt risk. An expected-state source that trusts a reported receipt can miss a lost effect.

The dashboard’s 42 historical synthetic executions are a third population, separate from both benchmarks. Its static evidence includes outcome summaries and event types. Original submitted text and raw trace payloads were omitted. Four fixed local walkthroughs can also be executed separately.

For dashboard checks, install the root Python environment first. In `web`, run `npm ci --ignore-scripts`, `npm run lint`, `npm run typecheck`, `npm run build`, `npx playwright install chromium` and `npm test`. The browser suite tests the public application, absence of legacy account routes under synthetic account settings, and each recorded and local walkthrough. Account-specific tests belong to the privately operated edition. See [deployment status](DEPLOYMENT_STATUS.md) for the supported scope.
